# OSCAL Scribe architecture and implementation decisions

## Assessment before implementation
OSCAL Lens inspected at commit f4156824e76a776c1f9bb684a103f0ec78fd0e5f. No changes are made to that repository. Reuse its engine/model detection, flattening, import traversal, alterations, parameter substitution, provenance, mapping helpers and escaped control rendering. Keep these modules byte-for-byte in src/shared/lens, with upstream regression tests and provenance; this can later become a shared package without editing Lens now. Lens explicitly does not implement complete profile resolution (merge/custom/metadata reconciliation). Its preview must not become our authoritative baseline. A pinned OSCAL CLI resolves profiles during publication; resolved catalogues and every source are retained. Lens renders the authoritative catalogue with source comparisons when unambiguous. Schemas are official version-specific NIST JSON schemas; schema validity is not compliance certification.

## Repository
src/web: TypeScript structured editor. src/api: Functions, shared authorization and repository adapters. src/shared: OSCAL document creation, validation and Lens modules. infrastructure: Terraform. scripts: controlled publication and deployment. demo: removable, opt-in NIST Low/Moderate and fictional SOC sources. tests: API/security/OSCAL and inherited Lens regressions. docs: deployment, threat model, API and decisions. Azure Pipelines templates are supplied; local deployment works before Azure DevOps is configured.

## Cosmos model
Container `ssps`, partition key /sspId. Current metadata/document id=current, immutable revisions id=revision:N, attestation id=attestation:UUID, audit id=audit:UUID share the SSP partition. A transactional batch conditionally replaces current (ETag) and creates revision/audit, preventing lost updates and partial history. ACL changes and attestations also use conditional batches. Access is checked against current ACL before any historical read. List queries are server-built and parameterized, scoped to owner/ACL unless Security. Archive retains history.
Container `content`, partition key /releaseId. Immutable content releases store each source and resolved catalogue as bounded chunks (full SP800-53 catalogue exceeds Cosmos's 2 MB item limit), with SHA256, manifest and versions. A separate `active` pointer changes only after validation, resolution and full upload; failed publication never advances it. Historical releases remain addressable. Functions identity has content read only and SSP read/write; publisher has content write. No content write HTTP route exists.

## API contract
Authenticated GET /api/me; GET /api/content (approved profiles/components); GET /api/content/{release}/{profile} (resolved baseline).
GET/POST /api/ssps; GET/PUT /api/ssps/{uuid}; POST /api/ssps/{uuid}/archive; POST /api/ssps/{uuid}/share; GET /api/ssps/{uuid}/revisions[/{number}]; POST /api/ssps/{uuid}/attest; POST /api/ssps/{uuid}/validate.
Create accepts profileId, releaseId and systemName. Update accepts only oscal plus If-Match revision token. Dedicated operations handle ACL/archive/attestation. 401 missing identity, 404 inaccessible object, 403 insufficient access, 409 conflict, 422 invalid OSCAL. Maximum request 1 MB, depth 64 and bounded node count. No arbitrary URLs/queries accepted.

## Entra and authorization
Single-tenant SPA app registration with authorization-code + PKCE (MSAL); API access tokens cryptographically verified for tenant issuer, API audience, delegated scope, expiry and signature via tenant JWKS. API never trusts browser identity headers or supplied owner/roles. Enterprise assignment required; application roles User and Security. Immutable tid/oid identities. The SPA requests access_as_user scope and uses bearer tokens on /api; no client secret or local password. Static Web App links a separately managed Function App; JWT validation remains mandatory even for direct Function URLs. Shared canRead/canEdit/canShare/canAttest/canAdminister checks every operation. Owners and Security manage shares/attest; editors modify content only. SSP system roles never grant application permissions.

## Terraform resources
Resource group, Standard Static Web App (required for linked Functions), Linux Consumption Function App + storage account, managed identity, Cosmos serverless SQL database and containers with local keys disabled, scoped Cosmos data RBAC, Log Analytics/Application Insights, Entra registration/service principal/scopes/roles and backend link. No Cosmos secrets. Function runtime storage uses managed identity where supported. Separate application/infrastructure/content pipelines. Test region defaults configurable; no apply until target subscription/tenant selected. Terraform state must use a private encrypted Azure Storage backend before shared use.

## Assumptions and deployment decisions
“Medium” means NIST Moderate. Official SP800-53 Rev5 catalogue and Low/Moderate unresolved profiles are pinned, downloaded by a separate demo command and published only with explicit demo operation. Fictional SOC covers centralized logging, monitoring, incident response and threat monitoring; coverage is explicitly partial with system responsibilities. No compliance claim. Default UI has no sample data or mock authentication; offline demo server binds loopback only and is separate from production Functions.
Azure tenant/subscription, region, budget and initial user assignments require user input before deployment. Azure DevOps organization/service connections require account setup; scripts and pipelines are prepared first. No major architectural substitution is proposed.
